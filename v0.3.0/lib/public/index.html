Public Interface

BondGraphToolkit — Module
BondGraphToolkit

A bond-graph dialect of ModelingToolkit: elements, junctions and two-ports are ordinary MTK systems, bonds are connects between PowerPorts, and models simulate with mtkcompile → ODEProblem → solve.

Sign convention (Karnopp, Margolis & Rosenberg 2012, §§2.2, 3.1, 3.3): a bond's half-arrow is the positive direction of power; element laws are written in the variables of their bond as drawn; at a junction the shared variable is unsigned and the sum is signed, + for bonds into the junction and − for bonds out of it.

source

Power port

BondGraphToolkit.PowerPort — Function
PowerPort(; name)

The connector through which an element exchanges power: effort e and flow f. MTK counts f positive into the component that owns the port. A bond is a connect from an outgoing port (an element's pout, a two-port's p2, a junction's outgoing free port) to an incoming one (an element's power, a two-port's p1, a junction's incoming free port); see Concepts and Conventions.

One-port elements

BondGraphToolkit.Se — Function
Se(E; name)
Se(; name)

Effort source, e = E. E is a number or any expression of t and system variables (an expression of another subsystem's variables needs @named). Without E, the effort comes from the signal connector input::RealInput (a modulated source, MSe). Conventionally its bond points away from the source: connect pout, or make it a junction member se => :pout.

source
BondGraphToolkit.Sf — Function
Sf(F; name)
Sf(; name)

Flow source, f = F. F is a number or any expression, as for Se. Without F, the flow comes from input::RealInput (MSf). Conventionally its bond points away from the source: connect pout, or make it a junction member sf => :pout.

source
BondGraphToolkit.Resistance — Function
Resistance(; name, R = 1.0)

Resistance, e = R f. Conventionally its bond points into it, so it dissipates e f = R f² ≥ 0. Drawn the other way it keeps its law and delivers power.

source
BondGraphToolkit.Compliance — Function
Compliance(; name, C = 1.0, q = 0.0)

Compliance with displacement state q: q̇ = f, e = q / C. q is the initial displacement. For a spring of stiffness k, C = 1/k. Conventionally its bond points into it. In derivative causality (its displacement fixed by other states), pass q = nothing: an initial value would over-determine the initialisation.

source
BondGraphToolkit.Inertia — Function
Inertia(; name, I = 1.0, p = 0.0)

Inertia with momentum state p: ṗ = e, f = p / I. p is the initial momentum. Conventionally its bond points into it. In derivative causality (its flow fixed by other states, e.g. two inertias on one 1-junction), pass p = nothing: an initial value would over-determine the initialisation. See Concepts and Conventions for steering which momentum MTK keeps as a state.

source
BondGraphToolkit.Mass — Function
Mass(; name, m = 1.0, v = 0.0)

Mechanical shorthand for Inertia with mass m and initial velocity v: I = m, p = m*v. Its bond conventionally points into it (Karnopp §3.1).

source
BondGraphToolkit.Spring — Function
Spring(; name, k = 1.0, x = 0.0)

Mechanical shorthand for Compliance with stiffness k and initial displacement x: C = 1/k, q = x. Its bond conventionally points into it (Karnopp §3.1).

source
BondGraphToolkit.Damper — Function
Damper(; name, c = 1.0)

Mechanical shorthand for Resistance with damping coefficient c: R = c. Its bond conventionally points into it (Karnopp §3.1).

source
BondGraphToolkit.De — Function
De(; name)

Effort detector: outputs the effort of its bond as output::RealOutput and carries no power (f = 0), so it doesn't change the model. It sits on a 0-junction, where every bond shares the effort it reads (Borutzky 2011, Ch. 3 p. 116). Write its bond like a passive element's, from the junction into the detector (member de); it carries no power, so the direction doesn't change the model.

source
BondGraphToolkit.Df — Function
Df(; name)

Flow detector: outputs the flow of its bond as output::RealOutput and carries no power (e = 0). It sits on a 1-junction, where every bond shares the flow it reads. Write its bond like a passive element's, from the junction into the detector (member df); it carries no power, so the direction doesn't change the model.

Junctions

BondGraphToolkit.Junction0 — Function
Junction0(members...; name)

0-junction: every bond shares one effort and Σ ± fᵢ = 0, + for bonds into the junction. A member is an element x (its bond points from the junction into x), x => :pout (its bond points out of x, into the junction), or a free port that other junctions and two-ports bond to with connect: :a (the bond leaves the junction) or :a => :in (it enters). A plain connect of element and free ports is itself a 0-junction.

@named rc = Junction0(sf => :pout, R, C)   # Sf ⇀ 0, 0 ⇀ R, 0 ⇀ C
source
BondGraphToolkit.Junction1 — Function
Junction1(members...; name)

1-junction: every bond shares one flow and Σ ± eᵢ = 0, + for bonds into the junction. Members as in Junction0.

@named m = Junction1(se => :pout, R, C)   # Se ⇀ 1, 1 ⇀ R, 1 ⇀ C

Two-ports

BondGraphToolkit.TF — Function
TF(; name, m)

Transformer with modulus m: e₁ = m e₂, f₂ = m f₁ (Karnopp Eq. 3.9). Port p1 is the bond into it, p2 the bond out: Se ⇀ TF ⇀ I is connect(se.pout, tf.p1) and connect(tf.p2, mass.power). m can be an expression (modulated transformer, MTF); build it with @named when the expression uses other subsystems' variables. Without m, the modulus comes from input::RealInput. MTK keeps an algebraic equation for a modulus read from a signal, so solve with a DAE-capable solver such as Rodas5P.

source
BondGraphToolkit.GY — Function
GY(; name, r)

Gyrator with modulus r: e₁ = r f₂, e₂ = r f₁ (Karnopp Eq. 3.11). Port p1 is the bond into it, p2 the bond out. r can be an expression (modulated gyrator, MGY); build it with @named when the expression uses other subsystems' variables. Without r, the modulus comes from input::RealInput; solve with a DAE-capable solver, as for TF.

source

Custom elements

BondGraphToolkit.@oneport — Macro
@oneport function Name(args...; name, kwargs...) ... [laws] end

Define a one-port element. The body can use e and f, the effort and flow of the element's bond along its half-arrow, and must end with the vector of laws. The macro adds the ports power (bond into the element) and pout (bond out of it, see bond_ports) and wraps the laws in a System, as an MTK @component; MTK finds the unknowns and parameters itself. A signal connector the body defines as input (RealInput) or output (RealOutput) becomes part of the element.

The names e, f, power and pout are taken: an argument with one of them throws, and a @parameters f (a frequency, say) clashes with the bond's flow. Call it ν or freq.

source
BondGraphToolkit.@twoport — Macro
@twoport function Name(args...; name, kwargs...) ... [laws] end

Define a two-port element: port p1 is the bond into it, port p2 the bond out of it. The body can use the bond variables e1, f1 (port 1) and e2, f2 (port 2), each flow positive along its bond's half-arrow, and must end with the vector of laws, written as in the books (e.g. Karnopp Eq. 3.9). The macro adds the ports and wraps the laws in a System, as an MTK @component. Signal connectors and taken names (e1, f1, e2, f2, p1, p2) as for @oneport.

MTK counts every port's flow positive into the component, so f2 = -p2.f; write the laws in e1, f1, e2, f2 and this sign is handled for you.

MTK Standard Library adapters

BondGraphToolkit.ElectricalAdapter — Function
ElectricalAdapter(; name)

Bond to an MTKSL electrical network connected between pins p and n: e = p.v - n.v (voltage across the network). Bond it through power when the network receives power (f = current into the network at p) and through pout when it supplies it (f = current out of the network at p); either way power is conserved. A grounded network uses connect(adapter.n, ground.g).

source
BondGraphToolkit.TranslationalAdapter — Function
TranslationalAdapter(; name)

Bond to an MTKSL Translational (velocity-based) network at flange: e = force on the network, f = flange.v through power and f = -flange.v through pout.

source
BondGraphToolkit.TranslationalPositionAdapter — Function
TranslationalPositionAdapter(; name, s = nothing)

Bond to an MTKSL TranslationalPosition network at flange: e = force on the network, f = ds/dt through power and f = -ds/dt through pout. s is the flange's initial position; leave it nothing when the MTKSL side already sets it.

source
BondGraphToolkit.RotationalAdapter — Function
RotationalAdapter(; name, phi = nothing)

Bond to an MTKSL Rotational network at flange (fixed support): e = torque on the network, f = dφ/dt through power and f = -dφ/dt through pout. phi is the flange's initial angle; leave it nothing when the MTKSL side already sets it.

source
BondGraphToolkit.HydraulicAdapter — Function
HydraulicAdapter(; name)

Bond to an MTKSL IsothermalCompressible network at port: e = port.p, and f = volume flow into the network at the fluid's reference density, -port.dm / port.ρ, through power (out of the network through pout). Connect the HydraulicFluid in its own statement (connect(fluid, src.port)), not in the same connect as the adapter.

Equations and drawing

BondGraphToolkit.bgequations — Function
bgequations(sys; rename = Dict())

The equations of the model sys in terms of its states, as full_equations of the compiled model (sys is compiled with mtkcompile unless it already is). rename maps model variables or parameters to the names to show instead, e.g. Dict(model.C.q => x, D(model.C.q) => ẋ, model.R.R => b). Renaming a variable also renames its derivative, unless the derivative has its own entry. The keys may come from sys itself or from its compiled form. The model is not modified: for a renamed variable in a solution, add an alias equation such as x ~ model.C.q to the model.

@variables x(t) ẋ(t)
latexify(bgequations(model; rename = Dict(model.C.q => x, D(model.C.q) => ẋ)))
source
BondGraphToolkit.BondGraph — Type
BondGraph(x)

The bond graph of x as data: of a model, of a bgplot drawing, or x itself when it is a BondGraph. Its fields are nodes and bonds; it is displayed as the list of its bonds (Se:V ⇀ 1:je) and drawn with bgplot.

  • nodes: one (; id, kind, label) per junction (kind = :junction, label "0" or "1"), element (:element) and two-port (:twoport), labelled type:name as in Karnopp's figures ("C:s", "TF:lever"). id is the path to the subsystem.
  • bonds: one from => to pair of node ids per bond, following its half-arrow.

A connect from an outgoing port (pout, p2, a junction's outgoing free port) to an incoming one (power, p1, a junction's incoming free port) is one bond. A connect of more than two power ports, or of two with the same role (e.g. two elements' power ports), is a 0-junction and gets its own node.

A subsystem with a power port is drawn as one element, even when it is a composite model inside: that's how hand-written elements are recognised. An element bonded through both power and pout is an error: a one-port has one bond.

source
BondGraphToolkit.bgplot — Function
bgplot(x; format = :svg)

Draw the bond graph of x, a model or a BondGraph, the way plot draws a solution. The drawing follows the textbook layout: the power path through junctions and two-ports runs left to right, and each element sits beside its node, with half-arrow bonds, 0/1 junctions and type:name labels.

  • format = :svg: the drawing. It appears in the VS Code plot pane, Jupyter, Pluto and the docs; in a terminal REPL it opens in the default viewer.
  • format = :tikz: a standalone LaTeX/TikZ document in the style of the docs' figures, shown as text. Compile it with pdflatex, or copy its tikzpicture (and the bgarrow declaration) into a paper.
  • format = :dot: the Graphviz DOT source, shown as text.

Save any of them with bgsave.

source
BondGraphToolkit.bgsave — Function
bgsave(path, x)

Save the bond graph of x (a model, a BondGraph or a bgplot) to path, in the format of its extension: .svg, .png, .pdf (rendered by Graphviz), .tex (TikZ, see bgplot) or .dot. Returns path.
